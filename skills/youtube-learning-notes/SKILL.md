# YouTube Learning Notes

YouTube 영상 한 편을 입력받아 **자막과 스크린샷이 결합된 한국어 학습 노트**(Markdown)를 만들어내는 워크플로우. 영상을 다시 보지 않아도 핵심 흐름·시각 정보·인용을 파악할 수 있도록 정리한다.

## 언제 쓰는가

- 사용자가 YouTube URL을 주면서 "정리/요약/학습 노트/공부자료/스크립트로" 같은 요청을 할 때
- 강의·발표·인터뷰·튜토리얼처럼 시각 정보(슬라이드, 데모 화면, 도표)와 발화 내용을 동시에 옮겨야 할 때
- "Slack에 공유할 영상 요약", "회의록처럼 만들어줘"라는 요청에서도 영상이 출처면 우선 검토

단순히 "이 영상 무슨 내용이야?" 같은 한 줄 답변이면 이 스킬을 켜지 말고 짧게 답한다. 노트 산출물이 목적일 때만 쓴다.

## 전체 흐름

1. 입력 수집 — URL, 노트 언어(기본 한국어), 노트 저장 경로
2. 영상·자막 다운로드 (`yt-dlp`)
3. 자막(.srt) 파싱 → 장면/포인트 선정 (기본 10~20개, 영상 길이에 따라 8~25개)
4. 각 시점 스크린샷 추출 (`ffmpeg`)
5. **스크린샷-자막 매칭 검토 (필수 QA)** — 이미지를 직접 보고 자막 섹션과 어울리는지 확인
6. 한국어 학습 노트(.md) 작성 — **내용을 함축한 Obsidian 호환 파일명**으로 저장

각 단계의 상세 절차는 아래에 정리한다. `scripts/`의 보조 스크립트는 반복 작업을 줄이기 위한 것이며, 반드시 써야 하는 것은 아니다.

### 작업 원칙 (효율)

- **독립적인 도구 호출은 한 번에 병렬로 실행한다.** 여러 스크린샷을 검토할 때는 한 메시지에서 `Read` 호출을 병렬로 묶는다. 스크린샷 추출/재추출은 `extract_screenshots.py` 한 번 호출에 여러 `--shot`을 전달해 한 프로세스에서 처리한다(이쪽은 병렬 Bash가 아님).
- **불필요하게 되묻지 않는다.** 기본값(한국어 노트, 표준 저장 경로)으로 진행 가능하면 진행하고, 막히는 지점에서만 확인한다. URL과 폴더 접근만 확실하면 끝까지 자동으로 완수한다.
- **각 단계의 산출물을 검증하고 넘어간다.** 다운로드 후 파일 존재·길이 확인, 추출 후 이미지 확인 — 실패를 다음 단계로 끌고 가지 않는다.

---

## 1단계 — 입력 수집

사용자에게 한 번에 확인:
- YouTube URL (필수)
- 노트 언어 (기본: 한국어)
- 저장 폴더 (기본: 사용자 마운트 폴더 또는 `outputs/youtube_<해시>/`)
- 톤·길이 선호 (선택; "압축적"=영상 1분당 ~50자, "상세"=1분당 ~150자, "회의록 톤" 등. 기본은 1분당 80~150자)

폴더 접근 권한이 없으면 `mcp__cowork__request_cowork_directory`로 작업 폴더를 먼저 요청한다. 다운로드 자체를 사용자에게 위임할 가능성이 있으니, 폴더 마운트는 1단계에서 받아두는 편이 안전하다.

## 2단계 — 다운로드

### 기본 명령어 (검증된 옵션)

```bash
yt-dlp \
  -f "bv*[ext=mp4]+ba[ext=m4a]/mp4" \
  --write-sub --write-auto-sub \
  --sub-langs "ko,en" \
  --convert-subs srt \
  -o "%(title)s.%(ext)s" \
  "<URL>"
```

- `bv*[ext=mp4]+ba[ext=m4a]/mp4` — mp4 비디오 + m4a 오디오를 합쳐 안정적인 mp4 산출. 코덱 문제로 합치기 실패하면 `/mp4` fallback이 단일 mp4를 받는다.
- `--write-sub --write-auto-sub` — 수동 자막이 있으면 그걸, 없으면 자동 생성 자막을 받는다.
- `--sub-langs "ko,en"` — 한국어를 우선, 없으면 영어. 다른 언어가 필요하면 사용자 확인 후 조정.
- `--convert-subs srt` — 이후 단계에서 파싱하기 쉬운 SRT로 통일.

### 샌드박스 네트워크 차단 대응 (중요)

Cowork/제한된 샌드박스에서는 YouTube/googlevideo 도메인이 차단되어 `yt-dlp`가 실패한다. 이 경우 즉시 fallback으로 전환한다:

1. 사용자에게 자신의 머신에서 동일한 `yt-dlp` 명령을 실행하도록 안내 (명령어를 복사 가능한 코드 블록으로 제공)
2. 받은 파일들이 들어있는 폴더를 `mcp__cowork__request_cowork_directory`로 마운트 요청
3. 마운트 후 그 폴더 안의 `.mp4`와 `.srt`를 입력으로 사용해 3단계로 진행

다운로드 실패 시 무한 재시도하지 말고, 한두 번 안에 fallback을 제안한다. 사용자의 시간을 아끼는 것이 우선이다.

### 산출물 확인

다운로드 후 다음을 확인하고 다음 단계로 넘어간다:
- `<title>.mp4` 존재 + ffprobe로 duration이 0이 아닌지
- `<title>.ko.srt` 또는 `<title>.en.srt` 중 하나 이상 존재
- 자막 파일이 비어있지 않은지 (`wc -l`이 0이면 자동자막 생성에 실패한 것 → 사용자에게 알리고 다른 영상 또는 수동 입력 권유)

## 3단계 — 자막 파싱 & 장면 선정

`scripts/parse_srt.py`를 사용하거나 같은 로직을 직접 구현한다. 이 스크립트는 SRT를 시간 정렬된 큐(cue) 리스트로 읽어 들이고, 옵션으로 첫 N개 큐를 미리보기로 보여준다.

### 장면 선정 휴리스틱

- **개수**: 10~20장이 기본. 영상이 짧으면(<10분) 8~12장, 길면(>30분) 15~25장.
- **균등 배치**가 아니라 **의미 단위로 끊기**: 화자가 새 주제를 꺼내거나, 자막에 "다음으로", "Next", "결론은" 같은 전환 신호가 있는 시점 우선.
- 자동 생성 자막은 오타/문장 경계가 부정확하니, 시간 간격이 너무 좁은(<15초) 후보는 합치고, 너무 긴(>3분) 구간은 중간 지점을 추가.
- 슬라이드·데모 화면이 바뀔 가능성이 높은 지점을 우선. 모델 본인이 영상을 못 봤더라도 자막 흐름으로 추측 가능하다.

각 후보에 대해 `{시:분:초, 자막 발췌, 추정 토픽}` 표를 잠시 만들고 다음 단계에서 이미지를 매칭해 검증한다.

## 4단계 — 스크린샷 추출

각 시점에 대해 ffmpeg로 한 프레임씩 뽑는다. `scripts/extract_screenshots.py`가 일괄 처리하지만, 한 장만 다시 뽑을 때는 직접 실행이 편하다.

### 단일 프레임 명령

```bash
ffmpeg -y -ss <HH:MM:SS> -i "<input.mp4>" -vframes 1 -q:v 2 "<output.jpg>"
```

- `-ss`를 `-i` 앞에 두면 빠른 seek + 정확한 프레임 디코드 균형이 좋다.
- `-q:v 2` — JPEG 품질 우수 (낮을수록 고화질, 2가 거의 무손실에 가까움).
- 출력 파일명 표준은 `scene_{NN}_{HHhMMmSSs}.jpg` (예: `scene_01_00h00m45s.jpg`) — **2자리 장면 번호 + `HHhMMmSSs` 타임스탬프**. `extract_screenshots.py`가 이 형식으로 자동 생성하므로, 노트의 `![]()` 링크에는 **스크립트가 실제로 만든 파일명을 그대로** 쓴다.

## 5단계 — 스크린샷↔자막 매칭 검토 (QA, 가장 중요한 단계)

**모든 스크린샷을 직접 검토한 뒤에만 6단계 노트 작성으로 넘어간다.** 자동 자막은 화면 전환과 타이밍이 어긋날 때가 잦고, ffmpeg는 검은 화면·로딩 화면·관계없는 컷오프 프레임을 잡을 수 있다. 이 게이트가 노트 품질을 좌우한다.

### 절차

1. **모든 스크린샷을 `Read` 도구로 직접 본다.** 한 메시지에서 여러 이미지의 `Read`를 **병렬로 묶어** 한 번에 확인하면 빠르다 (이미지를 직접 인식할 수 있다).
2. 해당 시점의 자막 큐와 비교해 다음을 평가:
   - 이미지에 보이는 텍스트/슬라이드 제목/시각 요소가 자막 토픽과 부합하는가?
   - 화면이 검정/광고/인트로/엔딩/트랜지션 블러 등 **노이즈**인가?
   - 같은 장면이 여러 번 잡혀 **중복**인가?
3. 부적절한 장면들을 모아 **±20초 범위에서 후보 시점을 다시 뽑아** ffmpeg로 재추출한다. 재추출도 여러 장이면 한 번에 처리하고, 다시 병렬 `Read`로 확인한다.
   - 예: `00:12:30`이 검은 화면이면 `00:12:10`, `00:12:50`을 시도.
4. 통과한 장면만 노트에 넣는다. 결과적으로 일부 후보가 사라져도 괜찮다 — 양보다 정합성이 중요.

실제 운용에서 평균 4장 교체로 효과가 검증된 단계다. 모든 스크린샷을 한 번씩 보고 통과분만 노트에 넣는다.

## 6단계 — 한국어 학습 노트 작성

`assets/note_template.md`의 구조를 그대로 따른다. 핵심 원칙:

### 파일명 규칙 — 내용을 함축한 제목으로 (Obsidian 호환)

노트를 다 쓴 뒤, 그 내용을 한눈에 알아볼 수 있는 **한국어 제목**으로 파일명을 짓는다. 파일명을 `notes.md`나 영상 ID 같은 무의미한 이름으로 두지 않는다.

제목 짓는 법:
- 영상 원제를 그대로 베끼지 말고, **노트의 핵심 주제를 압축**한다. "무엇에 대한 영상인지"가 파일명만 보고 드러나야 한다. (원제가 이미 충분히 설명적이면 다듬어서 사용)
- 보통 **15~50자**의 명사구. 예: `Claude Code 서브에이전트로 멀티 에이전트 워크플로우 구축하기`, `RAG 파이프라인 청킹 전략 5가지 비교`.

Obsidian에서 안전한 파일명으로 만들기 — 아래 문자는 제거하거나 치환한다:
- **금지 문자** `\ / : * ? " < > |` 와 링크/태그 충돌 문자 `# ^ [ ] |`
   - 콜론 `:` → ` - ` (공백·하이픈·공백) 로 치환. 예: `제목: 부제` → `제목 - 부제`
   - 슬래시 `/` → `-` 또는 공백
- **이모지·제어문자** 제거, **양 끝 공백과 끝 마침표(`.`)** 제거
- 단어 사이는 자연스러운 공백 유지 (Obsidian은 공백 파일명을 정상 지원하므로 억지로 하이픈/언더스코어로 바꾸지 않는다)
- 길이가 확장자 제외 **100자**를 넘으면 **단어 경계에서 자른다** (단어 중간에서 끊지 않는다)

**엣지케이스 폴백(순서대로 적용)**:
1. 정제 후 제목이 비면 → 영상 원제를 같은 규칙으로 정제해 사용
2. 그래도 비면 → `youtube-note` 사용
3. 같은 폴더에 동일 파일명이 이미 있으면 → 끝에 ` (2)`, `(3)`… 접미사를 붙여 덮어쓰기를 피한다

> 날짜 프리픽스(`2026-05-30 제목.md`)는 기본적으로 붙이지 않는다. 사용자가 데일리/타임라인식 정리를 원한다고 밝힌 경우에만 `YYYY-MM-DD ` 프리픽스를 앞에 붙인다.

본문 H1 제목(`# ...`)과 파일명은 같은 주제를 가리킨다. 단, H1에는 부제·이모지를 자유롭게 써도 되고, 파일명에는 위 규칙을 적용한 안전한 형태를 쓴다.

### 본문 작성 원칙

- **영상을 보지 않아도 완벽히 이해 가능**해야 한다 — 시각 정보(슬라이드 텍스트, 화면 구성, 도표)를 텍스트로 옮겨라.
- **자동 자막의 오타는 문맥에 맞게 정정**하되, 원문 인용 모음에는 원래 자막 흐름을 살린다 (단, 명백한 음성인식 오류는 보정해도 됨 — 예: "엠씨피" → "MCP").
- **스크린샷은 인라인으로** `![장면 N — 설명](screenshots/scene_NN_HHhMMmSSs.jpg)` 형식으로 삽입하되 파일명은 스크립트가 만든 실제 이름을 쓴다 (상대경로 — Obsidian 보관함에서도 깨지지 않게).
- 모든 시간 표기는 `[MM:SS]` 또는 `[HH:MM:SS]`로 일관되게.

### 노트 섹션 구성 (필수)

```
# <영상 제목>

> 출처: <원본 URL>
> 길이: <HH:MM:SS> · 채널: <채널명>

## 한눈에 보는 요약
- 3~7개 불릿. 영상을 한 문장씩으로 압축. "왜 보는지 → 무엇을 다루는지 → 결론" 흐름.

## 장면별 상세 설명
### [MM:SS] 1. <장면 제목>
![장면 1 — <간단 설명>](screenshots/scene_01_00h00m45s.jpg)
- 화면 설명: <스크린샷에 보이는 시각 정보>
- 발화 핵심: <자막을 우리말로 정돈하고 보강>
- 메모: <필요시 부가 해설·연관 개념>

(장면 2, 3, ... 반복)

## 부록 — 실전 체크리스트
- 시청자가 바로 적용할 수 있는 액션 아이템. 영상이 튜토리얼/실무성이면 필수, 에세이/대담이면 생략 가능.

## 원문 인용 모음
- [MM:SS] "발화 그대로의 인용" — 자동자막이면 가벼운 정정만, 수동자막이면 원문 보존.
```

`assets/note_template.md`에 더 자세한 본보기가 있으니 새 노트마다 그걸 복사해 채우는 편이 빠르다.

### 작성 디테일

- **본문 H1 제목**은 영상 원제를 따르되, 한국어가 자연스럽지 않으면 부제로 한국어 요약을 덧붙인다. (파일명은 위 「파일명 규칙」을 따른다.)
- 장면별 설명은 **자막 그대로 옮기기 → 우리말로 정돈하기 → 필요한 배경 보강하기** 순서로 작성하면 빠지는 정보가 줄어든다.
- 화자가 코드/명령어/수식을 보여주면 코드 블록으로 옮긴다. 화면을 캡처만 하고 텍스트로 안 옮기면 검색 가능성이 떨어진다.
- 노트 길이는 보통 영상 1분당 80~150자. 너무 짧으면 정보 손실, 너무 길면 가독성 저하.

## 산출물 정리

작업 폴더는 다음과 같이 정리해 사용자에게 전달:

```
youtube_<해시 또는 슬러그>/
├── <영상 제목>.mp4
├── <영상 제목>.ko.srt                          # 또는 .en.srt
├── screenshots/
│   ├── scene_01_00h00m45s.jpg
│   ├── scene_02_00h02m10s.jpg
│   └── ...
└── <내용을 함축한 제목>.md                      # 최종 학습 노트 (6단계 파일명 규칙)
```

최종 노트 파일을 `present_files`로 공유하고, 마지막에 스크린샷이 상대경로(`screenshots/scene_NN_HHhMMmSSs.jpg`)로 잘 걸리는지 한 번 확인한다. Obsidian 보관함(vault) 안에 바로 넣을 거라면 이미지 상대경로가 노트 위치 기준으로 유효한지도 함께 점검한다.

## 보조 자원
